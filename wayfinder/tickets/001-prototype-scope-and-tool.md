## Question

§16 needs *some* participants to react to a mockup, but only one row of its assumption table explicitly requires a visual artifact — "Show a mockup of the agent conversation." The others (JD-match-tool willingness, case-study-simulation effort, estimator usefulness, mentee booking preference, document vault credibility) are phrased as verbal/hypothetical questions in §16's own sample wording and may not need a screen at all.

Decide, concretely:
1. Which of §16's six assumptions actually need a visual mockup vs. which can be tested as a plain question in the survey copy.
2. For the ones that do need a mockup — what tool builds it fastest at low fidelity (Figma, a coded static prototype, annotated screenshots/slides, or something else), given no tool has been chosen yet and no design work exists today (current repo is a single static HTML page, not a Figma file or design system).
3. Scope the mockup(s) tightly enough to stay inside the ≤10-minute total participant time budget (§16) — this is a budget shared with the survey questions themselves (ticket 003), so the mockup can't be elaborate.

Resolving this produces the actual mockup asset(s), linked from this ticket — not just the tool choice.
